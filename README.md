# GOFOLKS

GOFOLKS — городская социальная платформа для публикаций, совместных мероприятий и общения пользователей.

Этот документ описывает возможности проекта, настройку окружения, запуск сервера и проверку REST API и WebSocket через Postman.

## Возможности

- Регистрация и авторизация пользователей.
- Хеширование паролей с помощью bcrypt и защита приватных маршрутов с помощью JWT.
- Получение профиля текущего пользователя.
- Создание, просмотр, изменение и удаление публикаций.
- Создание мероприятий, просмотр списка, присоединение и выход участников.
- Чаты мероприятий с обменом сообщениями через WebSocket.
- Хранение основных данных в PostgreSQL и истории сообщений в MongoDB.

## Технологии

- **Go** — серверная часть.
- **PostgreSQL** — пользователи, публикации, мероприятия и связи между ними.
- **MongoDB** — история сообщений чата.
- **Gorilla Mux** — маршрутизация HTTP-запросов.
- **Gorilla WebSocket** — WebSocket-соединения.
- **JWT** — аутентификация.
- **bcrypt** — хеширование паролей.

## Запуск проекта

### Требования

Установите:

- версию Go, совместимую с `go.mod`;
- PostgreSQL;
- MongoDB;
- Postman — для проверки API (необязательно для запуска сервера).

### 1. Создайте базу PostgreSQL

Создайте базу данных `gofolks`. В pgAdmin откройте Query Tool этой базы и выполните миграции в указанном порядке:

1. `migrations/001_core.sql`
2. `migrations/002_activities.sql`

**Не запускайте `migrations/001_activities_old.sql`** — это сохранённая старая версия миграции.

### 2. Настройте переменные окружения

В PowerShell из корня проекта выполните:

```powershell
Copy-Item .env.example .env
```

Откройте `.env` и укажите собственные параметры подключения. Пример:

```dotenv
PORT=8080
DATABASE_URL=postgres://postgres:YOUR_PASSWORD@localhost:5432/gofolks?sslmode=disable
MONGO_URI=mongodb://localhost:27017
MONGO_DATABASE=gofolks
JWT_SECRET=replace_with_a_random_secret_at_least_32_characters
```

Замените `YOUR_PASSWORD` на пароль пользователя PostgreSQL. Укажите случайный `JWT_SECRET` длиной не менее 32 символов. Не публикуйте реальные секреты.

### 3. Запустите сервер

Откройте терминал в корне Go-модуля — в каталоге, где находится `go.mod`, — и выполните:

```powershell
go mod download
go run ./cmd/server
```

При стандартной конфигурации сервер будет доступен по адресу `http://localhost:8080`.

Проверьте работу сервера:

```http
GET http://localhost:8080/api/health
```

Ожидаемый ответ:

```json
{
  "app": "GOFOLKS",
  "status": "ok"
}
```

Если сервер не запускается, проверьте, что PostgreSQL и MongoDB запущены, база `gofolks` создана, миграции выполнены, а значения в `.env` корректны.

## Общие правила API

Базовый адрес:

```text
http://localhost:8080
```

Запросы с JSON-телом должны содержать заголовок:

```http
Content-Type: application/json
```

Для защищённых HTTP-маршрутов добавьте:

```http
Authorization: Bearer YOUR_JWT_TOKEN
```

JWT выдаётся при регистрации или входе. Используйте токен текущего пользователя. Не публикуйте токены в репозитории и скриншотах.

## Маршруты API

### Служебный маршрут

| Метод | Путь | Назначение | Авторизация |
|---|---|---|---|
| `GET` | `/api/health` | Проверить доступность сервера | Не требуется |

### Авторизация и профиль

| Метод | Путь | Назначение | Авторизация |
|---|---|---|---|
| `POST` | `/api/auth/register` | Зарегистрировать пользователя | Не требуется |
| `POST` | `/api/auth/login` | Войти и получить JWT | Не требуется |
| `GET` | `/api/profile` | Получить профиль текущего пользователя | JWT |

### Публикации

| Метод | Путь | Назначение | Авторизация |
|---|---|---|---|
| `GET` | `/api/posts` | Получить список публикаций | Не требуется |
| `GET` | `/api/posts/{id}` | Получить публикацию по ID | Не требуется |
| `POST` | `/api/posts` | Создать публикацию | JWT |
| `PUT` | `/api/posts/{id}` | Изменить свою публикацию | JWT, владелец |
| `DELETE` | `/api/posts/{id}` | Удалить свою публикацию | JWT, владелец |

### Мероприятия

| Метод | Путь | Назначение | Авторизация |
|---|---|---|---|
| `GET` | `/api/activities` | Получить список мероприятий | Не требуется |
| `POST` | `/api/activities` | Создать мероприятие | JWT |
| `GET` | `/api/activities/mine` | Получить мероприятия текущего пользователя | JWT |
| `POST` | `/api/activities/{id}/join` | Присоединиться к мероприятию | JWT |
| `POST` | `/api/activities/{id}/leave` | Выйти из мероприятия | JWT |

### Чат

| Метод | Путь | Назначение | Авторизация |
|---|---|---|---|
| `POST` | `/api/chat/ticket` | Получить одноразовый билет для WebSocket | JWT |
| `GET` | `/api/chat/history?chat_id={chat_id}` | Получить историю сообщений | JWT и членство в чате |
| WebSocket | `/api/chat/ws?chat_id={chat_id}&ticket={ticket}` | Подключиться к чату | Одноразовый билет и членство в чате |

## Примеры запросов

### Регистрация

`POST /api/auth/register`

```json
{
  "username": "demo_user",
  "email": "demo@example.com",
  "password": "ExamplePassword123"
}
```

Используйте уникальные `username` и `email`. При успешной регистрации сохраните поле `token` из ответа.

### Вход

`POST /api/auth/login`

```json
{
  "email": "demo@example.com",
  "password": "ExamplePassword123"
}
```

Скопируйте `token` из ответа и используйте его для защищённых маршрутов.

### Создание публикации

`POST /api/posts` — с JWT.

```json
{
  "title": "Прогулка по Алматы",
  "description": "Ищу компанию для прогулки по городу",
  "location": "Алматы",
  "event_date": null
}
```

Сохраните `id` созданной публикации, чтобы проверить получение, изменение и удаление:

- `GET /api/posts/{id}`
- `PUT /api/posts/{id}`
- `DELETE /api/posts/{id}`

Изменять и удалять публикацию может её владелец.

### Создание мероприятия

`POST /api/activities` — с JWT.

```json
{
  "title": "Прогулка по городу",
  "description": "Ищем компанию для прогулки",
  "location": "Алматы",
  "activity_date": null,
  "max_participants": 4
}
```

Сохраните `id` и `chat_id` из ответа. Они понадобятся для участия и проверки чата.

### Присоединение к мероприятию

Войдите под другим пользователем и выполните запрос с его JWT:

```http
POST /api/activities/{id}/join
```

Для проверки участия используйте:

```http
GET /api/activities/mine
```

Чтобы выйти из мероприятия:

```http
POST /api/activities/{id}/leave
```

Подставляйте фактический ID мероприятия вместо `{id}`.

## Проверка чата

Чат использует WebSocket для обмена сообщениями, а MongoDB — для хранения истории.

1. Создайте мероприятие и убедитесь, что пользователь имеет право доступа к его чату.
2. Выполните `POST /api/chat/ticket` с JWT.
3. Скопируйте поле `ticket` из ответа. Билет одноразовый и действует около 30 секунд.
4. В Postman создайте **WebSocket request** и подключитесь по адресу, подставив реальные значения:

```text
ws://localhost:8080/api/chat/ws?chat_id=activity-1&ticket=YOUR_ONE_TIME_TICKET
```

5. Отправьте сообщение в JSON:

```json
{
  "content": "Проверка чата GOFOLKS"
}
```

6. Проверьте историю сообщений:

```http
GET /api/chat/history?chat_id=activity-1
```

Передайте JWT пользователя, который состоит в соответствующем чате. Если билет истёк или уже использован, запросите новый через `/api/chat/ticket`.

Для проверки хранения сообщений в MongoDB откройте MongoDB Compass, подключитесь по значению `MONGO_URI` из `.env` и найдите базу `gofolks`, коллекцию `messages`. Сообщение содержит данные чата, отправителя, текст и время создания.

Для обмена сообщениями между двумя пользователями оба должны иметь доступ к одной комнате и подключиться к ней со своими билетами.

## Безопасность

- Не добавляйте `.env` в GitHub.
- Не публикуйте пароли, JWT и значение `JWT_SECRET`.
- Храните в репозитории только `.env.example` с демонстрационными значениями.
- Передавайте JWT в заголовке `Authorization` для защищённых HTTP-маршрутов.
- Используйте одноразовый WebSocket-билет только для одного подключения.
- Доступ к истории и WebSocket-чату должен проверяться для участника соответствующего чата.
